# Triage — 9 items (2026-06-11)

Root causes + effort, grounded in code + live prod. Effort: S (≤½ day), M (1–2 days), L (multi-day).

## 🐞 Bugs

### 1. "Draft with HERALD" does nothing — **S, but tied to #5**
**Root:** The Draft button only renders for items with `status=accepted`. In prod, **32 of 34 items are `idea`**, 1 accepted, 1 scheduled. There is **no action anywhere to move an item idea→accepted**. So for almost every row the button simply isn't shown → "nothing happens."
**Fix:** Add a status workflow (Accept / move states) — best done as part of #5. Quick interim: allow drafting directly from `idea`.

### 2. "Add to calendar" item doesn't appear on the main calendar — **M**
**Root:** The calendar month grid is built **only from `PlatformPost`s** (`pp.effective_at`), not from `Post.scheduled_at`. `schedule_intake_item` creates a **channel-less Post (0 PlatformPosts)** — so it's invisible on the calendar. Confirmed: a scheduled Post "Kenya updating National Indust" exists with `platform_posts=0`.
**Fix:** When scheduling, create `PlatformPost`(s) from the intake's `channel_targets` for any connected `SocialAccount`; AND make the calendar also render channel-less scheduled Posts (planning items before a channel is connected).

### 3. Date-picker UI is rough — **S**
**Root:** Raw `<input type="datetime-local">` inside a bare `<dialog>`.
**Fix:** Style the dialog (padding, labels, buttons); optionally a nicer inline picker.

## ✨ Features

### 4. Approvals hand-off + owner routing — **M**
**Root:** `POST /agents/herald/draft` creates a `content_item` but **no `Approval` row**. The console queries `/approvals?assignee=me` (identity `platform-user`), so nothing shows. (The `pipeline.py` accepted-ideas path *does* create approvals, assigned to "joseph" — but our bridge doesn't use it.)
**Fix:** On draft, create a pending `Approval` assigned by **pillar→owner**:
`Agriculture→Carren · Energy→Dennis · AI→Joseph · Digital→Nduta · Minerals→Dennis` (default: workspace owner). Requires agent-service change (add `assignee` to draft) + Django bridge passes the mapped owner + deploy. Console approve already auto-creates a Post (done earlier).

### 5. Drafts CRUD + Kanban + full integration — **L (biggest)**
**Root:** A Kanban primitive exists (`Idea` has `unassigned/todo/in_progress/done` + `IdeaGroup` columns) but it's **separate from `ContentIntake`**. No "edit opens the existing item," no cross-links intake↔composer↔calendar.
**Fix:** Give intake items a workflow (To Do / In Progress / Done), make edit open the existing draft/Post in the composer, and wire intake → composer → calendar as one flow. Subsumes #1 and overlaps #2.

### 6. Analytics not pulling (followers/engagement) — **M, partly blocked**
**Root:** `AccountInsightsSnapshot` has **0 rows**. The `analytics-sync` beat task IS registered (hourly). The likely blocker: **LinkedIn personal (OIDC) can't read follower/engagement analytics** — that needs the same Community Management / Marketing API approval LinkedIn blocked. Mock/other platforms would populate.
**Fix:** Verify the sync runs; surface a clear "analytics not available for this connection" state; analytics light up per platform as APIs are approved.

### 7. Resend email reminders — **M**
**Root:** Email backend is **SMTP or console only** — no Resend, no reminder triggers.
**Fix:** Add a `resend` email backend branch (via `resend`/Anymail) + reminder jobs (e.g., approval pending, scheduled-post due). New integration.

### 8. Doc links on the calendar — **S**
**Root:** `reference_links` live on `ContentIntake`, not on the `Post` the calendar renders. So docs show on the intake board but not the calendar.
**Fix:** Carry/surface the intake's doc links on the scheduled Post's calendar card/detail.

### 9. Pipeline is static — **product decision, not a bug**
**Root:** `/console/pipeline` is a read-only mirror of agent-service `/threads` (CRM relationship dossiers — Proparco, BII, etc.). It's static because nothing advances threads from the platform. **HERALD is confirmed running on DeepSeek-V4** (verified live draft earlier).
**Decision needed:** keep as a CRM/relationship tracker, repurpose, or hide it for now.

## Recommended build sequence

1. **Content Workflow** (#5 + #1 + #2 together) — the core: item states (To Do/In Progress/Done), Accept→Draft works, edit-opens-existing, scheduled items show on the calendar. This is the backbone everything hangs off.
2. **Approvals + owner routing** (#4) — closes Sheet→draft→approve→publish, with the pillar→owner map.
3. **Polish bundle** (#3 date picker + #8 calendar doc links) — small, quick.
4. **Resend reminders** (#7) — once the workflow + approvals exist (reminders need events to fire on).
5. **Analytics** (#6) — partly gated by LinkedIn API approval; do the "graceful unavailable" state now, real data later.
6. **Pipeline** (#9) — decide its fate.
